# slides-mcp v0.2.1

Patch release — `create_slide` dogfood round 2. Hardens the primitive against real decks.

## Highlights

- **Deck-dimension-aware geometry.** `create_slide` now fetches the target deck's `pageSize` and scales archetype geometry at runtime. Fixes off-slide content on non-16×9 decks (Google's default 10×5.625, legacy 13.33×7.5, etc.). Archetype YAMLs remain authored against a 16×9 reference — scaling is transparent to the caller.
- **Content-driven color palette.** Agents can pass `content["pill_palette"]` (list of hex) or per-column `pill_hex` to drive per-slide visual identity, without editing a bundled theme or restarting the server. The theme palette is fallback only. Priority: `col["pill_hex"]` > `content["pill_palette"][i]` > theme `brand_accent` role.
- **Visual story extras on `3col_pill_cards`.** Rounded pill corners (`ROUND_RECTANGLE`), a colored title-accent bar under the title, and a small colored dot above each column — all color-matched to the pill for that column.
- **README rewrite** with mermaid diagrams for the high-level agent/MCP/Slides flow, create-slide sequence, and patch-slide sequence. New explainers for theme YAML, archetype YAML, and the compact DSL — what they are, where they live, and how the agent interacts with each.

## Fixes

- **Geometry clipping** (observed on `cap_new_primitive` from v0.2.0 dogfood): title + body text cut off at the right edge, only 2 of 3 columns visible. Root cause: archetype 16×9 geometry emitted verbatim on a 10×5.625 deck. Fixed via runtime pageSize scaling.
- **Pill text color** regression-guarded by new `test_pill_text_color_emits_opaque_white`. The observed dark-on-blue text on slide `cap_theme` was diagnosed as a hand-built artifact (shape IDs didn't match `create.py._new_id()`'s prefix) — `create.py` itself emits opaque white correctly.

## New API shape

`create_slide(..., content={title, lead?, columns: [{pill, body, pill_hex?}], pill_palette?, title_accent_hex?})` — the three new optional content keys are the color-driver hooks. Omit all three and the slide falls back to the theme's `brand_accent` for every pill (backward-compatible with v0.2.0 call sites).

## Known limits

- Slides API rejects write-side `TEXT_AUTOFIT` (response-only field). Long pill labels like `audit_deck_colors` (17 chars, 22pt bold) wrap inside pill bounds on scaled decks. Mitigation: keep pill labels ≤ ~12 chars, or reduce `pill_header.size_pt` in your theme.
- `normalize.py._extract_transform` reads `translateX/Y` but ignores `scaleX/Y`, so `get_slide` faithful mode reports `w_in = h_in = 3.281` for any API-created shape. Rendering is correct; only the DSL readback is wrong. Fix parked for a follow-up release.
