# v2.2.0 — Deck scripts, Markdown speaker notes, and a read model you can trust

v2.1 gave agents a raw `batchUpdate` passthrough. That works when the agent
already knows every id and value. It works badly when the edit depends on the
deck itself: "make every dark slide light", "swap this palette", "restyle
every title". The agent had to read the whole deck into its context, compute
hundreds of requests by hand and paste them back. v2.2 moves that loop into
the server.

## New: `run_deck_script`

The agent sends a short JavaScript function body. The server runs it against
the deck in a sandbox and applies the requests it queues.

```js
// input: {"from": "#1A73E8", "to": "#0B8043"}
for (const slide of deck.slides)
  for (const el of slide.elements)
    if (el.fill && el.fill.hex === input.from) emit(setFill(el, input.to, el.fill.alpha));
return {done: true};
```

- **Dry run is the default.** Nothing is sent; the reply is a per-slide
  preview of request kinds and of colours and fonts before and after.
- **Atomic phases.** Everything queued goes out as one `batchUpdate`, so a
  failing request leaves the deck untouched. `await commit()` splits the work
  when a later step must see what an earlier step created; the deck is re-read
  between phases.
- **Refused before any API call:** requests that name ids not in the deck,
  more than `max_requests` requests, and destructive kinds without
  `confirm_destructive=true`.
- **Warnings** when a font change drops a font weight, and when a font or
  size change will likely overflow a fixed-size text box.
- **Errors point at the script,** with the line and column in the agent's own
  source, or at the failing request with its index.
- **`render_slides`** returns up to six thumbnails after a real apply, so the
  agent can check the result by eye in the same call.
- **Helpers** for the requests agents get wrong most: colours, fills,
  backgrounds, text styles that keep font weight, resize with a pinned edge,
  text boxes with `autofit` off, Markdown notes.

The sandbox is embedded V8 (`mini-racer`, new dependency) in a child process
per call, with no filesystem, network, imports or timers. A CPU timeout kills
runaway loops and a wall-clock timeout bounds the whole call. It is built to
stop accidents, not attackers: the script runs with your own token against a
deck you named. `docs/adr/0004-deck-scripts-in-embedded-v8.md` records the
alternatives that were ruled out.

## New: `write_speaker_notes`

Speaker notes from Markdown, for many slides in one batch. The notes get real
formatting: bold, italic, bullets nested by indentation, and header-sized bold
paragraphs. Never literal `**`. `mode="append"` adds a paragraph after what is
there and needs no confirmation; replacing notes that are not empty needs
`confirm_destructive=true`.

`read_slides(..., notes_format="markdown")` reads notes back in the same form,
so what you write reads back unchanged.

## Fixed: the read model

These reached every read tool, not only scripts:

- **Transparent boxes read as white.** The API sends a white fill beside the
  "not rendered" flag; it is now reported as no fill.
- **Rotated, scaled and grouped elements had wrong positions.** Geometry is
  now the page-space bounding box, with group transforms composed and
  rotation reported.
- **Theme colours were dropped.** They now resolve to hex through slide,
  layout and master, and the theme slot name is kept.
- **Font weight was invisible.** Runs report their weight, so a semibold
  heading no longer looks like regular text.
- **Text offsets were in characters.** They are now UTF-16, which is what
  every `textRange` in a write request counts; emoji no longer shift styles.
- **Slide backgrounds** resolve through the same chain and appear in `raw`
  detail when they are not white.

`raw` detail adds `fill`, `outline`, `autofit`, `rotation_deg` and `parent_id`
only when they differ from the default, so the token cost of plain slides is
unchanged.

## New: audit line

Every applied batch, from any write tool, prints one JSON line to stderr
starting with `slides-mcp audit `: tool, deck id, request count and kinds,
plus the script hash and phase for deck scripts. Set `SLIDES_MCP_AUDIT_LOG` to
a file path to also append them to a file.

## Upgrade notes

- No breaking changes to existing tools or arguments.
- Write tools still need a token with the `presentations` scope. A real
  `run_deck_script` apply checks the scope first and says how to re-consent.
- The shipped skill now tells agents to prefer `run_deck_script` whenever the
  edits depend on deck data.
- Your MCP client has its own tool-call timeout. If it is shorter than
  `timeout_s`, the client gives up first while the script may still be running
  on the server.
