# v2.5.0 (unreleased)

## New: write receipts

Every write tool that changes a slide now returns thumbnails of the slides it
touched in the same reply, so an agent sees its change without a second
`render_thumbnail` call.

- **Which tools.** `exec_batch_update`, `add_section_footers` and a real
  `run_deck_script` apply. Not `write_speaker_notes` (a thumbnail cannot show
  speaker notes), not dry runs, not refused writes.
- **New `receipt` argument** on those tools: `medium` (default, 800x450,
  about 480 tokens each), `large` (1600x900) or `off`.
- **At most 3 slides per write.** Any others are listed by id in
  `thumbnails.not_shown_slide_ids`, with a hint to use `render_thumbnail`.
- **Thumbnails are fetched in parallel** and each is tried once. A failure,
  including Google's thumbnail rate limit (60 a minute per user, 300 a minute
  per project, shared with `render_thumbnail`), is a warning; the write is
  still reported as successful.
- `run_deck_script`'s `render_slides` keeps working: it now picks which
  slides the receipt shows (still up to 6), at the `receipt` size.

## Changed

- **Write tools return a list when thumbnails are attached:** the JSON body
  as a text block, then one image per slide. With `receipt="off"`, or when no
  thumbnail rendered, the reply is the plain JSON object as before. The body
  gains a `thumbnails` field.
- `run_deck_script` now attaches thumbnails after every real apply, not only
  when `render_slides` is given.
- `exec_batch_update` with `post_state="none"` now re-reads the deck once to
  find the touched slides, unless `receipt="off"`.

## Upgrade notes

- A client or script that reads a write tool's reply as one JSON object
  should pass `receipt="off"`, or read the first content block.
- Teams sharing the Cloud Run server share the project's thumbnail quota;
  see `docs/deploying-to-cloud-run.md`.
