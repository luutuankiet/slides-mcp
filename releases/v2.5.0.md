# v2.5.0 (unreleased)

## New: write receipts

Every write tool that changes a slide now returns thumbnails of the slides it
touched in the same reply, so an agent sees its change without a second
`render_thumbnail` call.

- **Which tools.** `exec_batch_update`, `add_section_footers` and a real
  `run_deck_script` apply. Not `write_speaker_notes` (a thumbnail cannot show
  speaker notes), not dry runs, not refused writes.
- **New `receipt` argument** on those tools: `medium` (default, 800x450,
  about 480 tokens each), `large` (1600x900) or `off`.
- **At most 3 slides per write.** Any others are listed by id in
  `thumbnails.not_shown_slide_ids`, with a hint to use `render_thumbnail`.
- **Thumbnails are fetched in parallel** and each is tried once. A failure,
  including Google's thumbnail rate limit (60 a minute per user, 300 a minute
  per project, shared with `render_thumbnail`), is a warning; the write is
  still reported as successful.
- `run_deck_script`'s `render_slides` keeps working: it now picks which
  slides the receipt shows (still up to 6), at the `receipt` size.

## New: apply a deck-script dry run by plan_id

A `run_deck_script` dry run now returns `preview.plan_id`. To apply it, call
`run_deck_script(deck_url, plan_id=..., dry_run=False)` with no script; the
script and input are not sent again.

- **Re-runs, never replays.** Applying a plan runs the stored script and
  input (with the dry run's limits) against the deck as it is now, so edits
  a colleague made since the dry run are picked up. The reply is the normal
  apply reply with its receipt thumbnails; nothing compares it with the dry
  run.
- **Bound and short-lived.** A plan lasts 1 hour, applies only to the deck it
  was made for and, on the hosted server, only for the person who made it.
  A successful apply uses it up. Over stdio plans live in process memory;
  `serve-http` keeps them in its Firestore database.
- **Destructive guard unchanged.** `confirm_destructive=True` is needed on
  the apply call when the re-run emits destructive kinds; confirming on the
  dry run does not carry over.
- **Errors** (kind `plan`): `plan_id` together with `script`; `plan_id`
  without `dry_run=False`; and an unknown, expired, used, wrong-deck or
  wrong-caller plan, which says to run the dry run again.

## New: place_image

`place_image` puts an SVG diagram or a public image URL onto a slide, either
into a placeholder box the user prepared or into an explicit box.

- **Placeholder first.** The user draws a box holding marker text (for
  example `{{DIAGRAM}}`) on a reference slide. The agent duplicates the slide
  and calls `place_image(deck_url, slide_id=..., svg=..., placeholder="{{DIAGRAM}}",
  confirm_destructive=True)`. The image replaces the box and keeps its object
  id. The replace is limited to that slide and needs `confirm_destructive`
  like any other destructive write.
- **Box.** `box={x, y, width, height}` in points places a new image there.
- **Fit (placeholder only).** `contain` (default) keeps the whole image and
  shrinks the box to its aspect ratio; `cover` keeps the box and crops.
- **SVG** is rasterised server-side at the target box's aspect ratio
  (3 px per point, capped below Google's 25 megapixel limit), hosted in the
  image bucket for one write and deleted afterwards, on success or failure.
  It needs the hosted server with `SLIDES_MCP_IMAGE_BUCKET` set; over stdio,
  or without a bucket, the error says what is missing. Text whose font is
  missing on the server is reported in `warnings`. References outside the
  document (`href` to a file or URL) are refused; use data: URIs.
- **image_url** needs no bucket and works over stdio. Google keeps the
  image's aspect ratio, so in a box its stored size can be smaller.
- **Errors** come back with `error.kind`: `hosting`, `svg` (quotes the
  renderer), `target` (unknown slide), `marker` (marker not on that slide,
  including a marker on its layout or master, which a slide-scoped replace
  cannot reach) or `google` (Google's own reason for rejecting the image).
- The reply is the usual write reply: post-state summary and a thumbnail of
  the slide, plus `placed{slide_id, object_ids, source, target}`.

## New: editable SVG (`place_image(editable=true)`)

`editable=true` turns the SVG into native Slides shapes the user can edit,
instead of an image. No bucket is needed, so it works over stdio too.

- **Subset.** `rect` (with `rx`/`ry` as a rounded rectangle), `circle`,
  `ellipse`, `line` with `marker-start` / `marker-end` as Slides arrowheads,
  plain `text`, and `g` with `translate` and `scale`. Fill, stroke, stroke
  width, dash, fill/stroke/overall opacity, also inside `style=""`; colours
  as hex, `rgb()` or basic names. The tool description lists it in full.
- **Fit and grouping.** The viewBox is scaled into the box, centred, the
  same way the image path fits it. Two or more elements are grouped and
  `placed.object_ids` holds the group; `placed.editable` is `true`.
- **Placeholder.** Each shape holding the marker is deleted (`deleteObject`,
  so `confirm_destructive=True` is required) and the drawing is placed in its
  box, in the same batch. `fit="cover"` is refused with `editable`.
- **Refused before any write.** `path`, `polyline`, `polygon`, gradients,
  patterns, filters, clip paths, masks, `rotate` / `skew` / `matrix`,
  `tspan`, `image`, `use` and zero-size elements come back as error kind
  `svg`, with every problem listed. Nothing is drawn.
- **Known losses.** The corner radius is Slides' fixed one (about 1/6 of the
  shorter side), any dash pattern becomes one dash style, and arrowhead size
  follows the line weight.
- **Fonts.** The first family in `font-family` is used and generic names
  become real ones (`sans-serif` to Arial, `serif` to Times New Roman,
  `monospace` to Courier New), because Slides draws any family it does not
  know in a serif font.
- The Docker image now installs `fonts-liberation2`; without it every SVG
  text element was dropped.

## Changed

- **Write tools return a list when thumbnails are attached:** the JSON body
  as a text block, then one image per slide. With `receipt="off"`, or when no
  thumbnail rendered, the reply is the plain JSON object as before. The body
  gains a `thumbnails` field.
- `run_deck_script` now attaches thumbnails after every real apply, not only
  when `render_slides` is given.
- `exec_batch_update` with `post_state="none"` now re-reads the deck once to
  find the touched slides, unless `receipt="off"`.

## Upgrade notes

- A client or script that reads a write tool's reply as one JSON object
  should pass `receipt="off"`, or read the first content block.
- Teams sharing the Cloud Run server share the project's thumbnail quota;
  see `docs/deploying-to-cloud-run.md`.
- To place SVG on the hosted server, set up the image bucket (one-time setup
  step 10 of `docs/deploying-to-cloud-run.md`) and redeploy so the image
  carries the fonts. A placed image's `sourceUrl` keeps the signed URL,
  which names the bucket and the service account's email; anyone who can
  read the deck can see it.
- New runtime dependency: `resvg-py`.
