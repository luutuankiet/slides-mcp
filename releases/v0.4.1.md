# v0.4.1 — Round-3 closed the agent-DX loop

Narrow patch: makes `uvx slides-mcp install` surface the v0.3.0 rules files to agents, and adds a slide-count-clarify anti-pattern to the prompt-→-slides workflow. Both fixes trace directly to the Round-3 intern gate — see the Why section.

## TL;DR

Two Round-3 interns tested the v0.3.0 theme brief end-to-end. Both produced coherent output AND both surfaced the same blind spot: an agent starting from a stale `uvx slides-mcp install` never sees that `rules/theme-coherence.md` and `rules/visual-presentation.md` exist. When one intern's briefing didn't work around it, `text_heavy_body` share regressed 10% → 40% on a 10-slide deck. v0.4.1 closes the signal gap so the next agent doesn't re-learn it the hard way.

## Why this release exists

Round-3 of the intern gate ran two subagents on the same sandbox deck with different briefs:

- **Scenario A** (markdown-as-prompt, 10 slides, navy+orange brief) returned **10/10 `brief_applied:true`** — infrastructure works — BUT `text_heavy_body` share rose to **40%** (was 10% in Round-2 with the same briefing style). The intern fell back to a stale `~/.claude/skills/slides-mcp/` that predated v0.3.0 and never read `rules/visual-presentation.md` (the doc that explicitly says "avoid `text_heavy_body` monoculture").
- **Scenario B** (direct-intent, 7 slides requested, **6 delivered**, teal+copper brief) read all 5 rules files fresh from the remote — because its briefing was hardened explicitly. Result: **17%** `text_heavy_body` (no regression) BUT silent under-delivery on the 7-slide count. User enumerated 6 slot roles; intern counted 6 and stopped. Defensible reading, wrong outcome.

Neither gap is infrastructure. Both are agent-facing signals that never arrived:

1. A stale install has no way to know it's stale. The install CLI's help text advertised 7 rules files when the package shipped 9.
2. A user who says "7 slides" and enumerates 6 roles is asking for a bridge. The rule doc never said so.

v0.4.1 fixes both signals.

## Highlights

| Change | What it does | Why it matters |
|---|---|---|
| `install_skill.py` HELP_TEXT rewrite | Lists ALL 9 installed files, including the v0.3.0 additions (`theme-coherence.md`, `visual-presentation.md`, `generate-from-intent.md`). Each NEW row is tagged `NEW` with a terse one-liner. | Agent reading install output now sees the full rules inventory — missing doc becomes visible missing doc. |
| `install_skill.py` re-install footer | Runtime output now ends with: *"Tip: re-run `slides-mcp install` after upgrading. Rules files evolve between versions; a stale install means agents skip new workflow guidance."* | Stale local skill was the #1 blind spot Round-3 surfaced. Calling it out costs nothing. |
| `generate-from-intent.md` Step 1 — "Slide count — clarify before silently under-delivering" | New subsection: when user's numeric count exceeds enumerated roles, add a bridge slide OR clarify. Never silently under-deliver. | Scenario B's 6-vs-7 failure mode, addressed in the rule doc that drives the Plan step. |

No server code changes. No API changes. No schema changes. This release exists purely to close agent-facing signal gaps Round-3 surfaced.

## Upgrade notes

- **Existing users SHOULD re-run `uvx slides-mcp install --global`** to pick up the v0.3.0 rules files plus this release's HELP_TEXT. Without it, agents continue to skip `theme-coherence.md` + `visual-presentation.md` and reproduce Round-3 Scenario A's 40% `text_heavy_body` regression.
- Installed file count 7 → 9. Re-install cleanly overwrites; `_copy_tree` is idempotent.
- No schema changes. No API changes. No behavior changes in any MCP tool.
- The server itself runs identically to v0.4.0 — all 23 tools, 181 tests, same brief resolution semantics.

## Hard truth

v0.4.1 is narrative, not code. The v0.3.0 infrastructure was fine — 10/10 `brief_applied:true` proves the brief contract is load-bearing. The regression Round-3 surfaced was a *stale install combined with a help text that lied about what `uvx slides-mcp install` actually installs*. Both fixes land here; tagged the same day as Round-3 closed.

Next substantive release is Phase 3 (AI image gen, stock search, Phosphor icons) or Phase 2.5 (`restyle_slides` retroactive repaint). User picks priority.
