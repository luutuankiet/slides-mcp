# v0.5.0 — typographic depth + variant selection

*Released: 2026-04-23*

The last mile of a presentation isn't raster imagery — it's typographic depth
and mood coherence. v0.5.0 ships both as first-class primitives. 24 tools →
**29 tools**; 181 tests → **337 tests**.

## Pivot

The v0.5.0 scope was originally Pexels stock-search (LOG-023 kickoff). That
direction was vetoed at session start: no image-vendor surfaces, no new
dependencies, no new API keys. The `[IMAGE: prompt]` placeholder stays as
the final deliverable for raster needs — not a stepping stone.

New scope: build captivating presentations from natural language using
**vanilla primitives alone** (fonts, colors, shapes), AND let the user pick
between visual moods before committing a theme.

## Highlights

| Surface | Before v0.5.0 | v0.5.0 |
|---------|--------------|--------|
| Character-range styling | escape-hatch-only (hand-rolled `updateTextStyle` with UTF-16 index math) | **Bespoke**: `update_text_style(range={"match": "..."})` — server resolves the range. Match / chars / paragraph / all. |
| Paragraph-range styling | same — escape-hatch-only | **Bespoke**: `update_paragraph_style` with same range language. |
| Current styling discovery | invisible in clean DSL | `get_slide(include_styles=True)` → top-level `_styles` map of runs. Opt-in, ~30 tok/slide when styled, 0 when plain. |
| Mood exploration | commit-and-pray | **3-step workflow**: `propose_brief_variants(intent)` → `generate_variants(content_list, briefs)` → `lock_variant(winner_id)`. Render thumbnails between steps; commit the winner, auto-delete losers. |

## New tools (5)

- `update_text_style(deck, slide_id, object_id, style, range)` — character-level styling with shared range language. Auto-thumbnail on write. Server-side substring match; ambiguous matches raise loudly.
- `update_paragraph_style` — paragraph-level. Alignment / line spacing / indent / space above/below.
- `propose_brief_variants(intent, n=3)` — pure function. 6 curated mood templates + keyword scoring (case-insensitive substring). Returns N distinct-accent briefs ready for `set_theme_brief` or `generate_variants`.
- `generate_variants(deck, content_list, briefs, variant_prefix)` — renders the same content under N briefs. Returns a manifest with per-variant slide_ids. Validates all briefs BEFORE any write.
- `lock_variant(deck, variant_id, variants_manifest)` — promotes winner's brief; deletes losers' slides. Partial-delete failures surface as warnings — winner still commits.

## Surface changes

- `get_slide` gains **`include_styles: bool = False`** — when True, clean + faithful mode projections append `_styles: {object_id: [runs]}` where each run carries non-default style fields only. Uniform plain-text shapes skipped (no signal).
- `projection.project()` signature extended (same flag threaded through).
- `rules/escape-hatch.md` narrowed: `updateTextStyle` / `updateParagraphStyle` are now in the "don't — use the bespoke tool" column.

## New skill docs (2)

- `rules/character-styling.md` (~155 lines) — range language reference, style subset tables, common recipes (emphasize first phrase, italicize a quote, center a quote, layer a typographic hierarchy from scratch), anti-patterns, discovery via `get_slide(include_styles=True)`.
- `rules/variant-generation.md` (~160 lines) — 3-step propose → generate → lock workflow, curated-mood keyword table, render-and-compare requirement, when-to-use-vs-not decision matrix, anti-patterns.

Both are linked from SKILL.md + auto-copied by `slides-mcp install`. Existing
users should re-run `uvx slides-mcp install --global` to refresh stale local rules.

## Round-4 intern evals — both PASSED

Two fresh sonnet subagents, independent context, skill-only guidance:

**D1 — typographic depth scenario.** Task: build an editorial-style slide with a 2×-bold accent-colored first word + an italic accent phrase inline.
- Tools used: `create_slide → get_slide → update_text_style (×2) → render_thumbnail → delete_slide`
- Range language: both edits used `{"match": "..."}` — the recommended default path
- No fallback to `exec_batch_update`; no wrong-first-guess on tool selection
- One friction item surfaced + fixed: `character-styling.md` now links to `get_slide(include_styles=True)` for `object_id` discovery before the first recipe

**D2 — variant selection scenario.** Task: user undecided on visual direction, show 3 distinct moods for a data-analytics-consultancy pitch.
- Tools used: `propose_brief_variants → generate_variants → render_thumbnail (×3) → delete_slide (×6)`
- Variants: confident enterprise (copper/teal), minimalist technical (blue/white), bold magazine (amber/charcoal) — all distinct at-a-glance
- `brief_applied:true` on **6/6** rendered slides
- Clean canonical path — no manual brief cycling

Both traces are the proof that the skill docs actually change agent behavior — interns discovered the bespoke tools from the rules docs and used them correctly without prompt coaching.

## Architecture

- New module: `src/slides_mcp/text_range.py` — pure range resolver + style normalizers. Shared by `update_text_style` + `update_paragraph_style`. Zero network, fully unit-tested.
- New module surface: `theme_brief.py` grows `propose_brief_variants` + 6 mood templates.
- New projection helpers: `_projected_styles`, `_run_to_dict`, `_is_default_run` in `projection.py`.
- Server composition: `generate_variants` composes `set_theme_brief` + `create_slide` internally; `lock_variant` composes `set_theme_brief` + `delete_slide`. Each new tool is a thin wrapper over existing primitives — no new API surface, no new deps.

## Invariants preserved

- **Decision O** (content-driven visual identity per call) — every new tool still accepts per-call overrides; theme-brief is a fallback only.
- **Decision P** (shapes-first, image-placeholder-as-fallback) — placeholder remains the final deliverable for raster needs; no vendor surfaces added.
- **Decision R/S/T** (in-deck meta-slide brief, resolution order) — variants read/write the same meta-slide channel; no server-side brand storage.
- **Renderer-not-brand contract** — MCP remains a single rendering engine; visual decisions live at call-site or in the user-controlled deck brief.

## Out of scope (deferred)

- Stock-search / AI image generation / any image-vendor surface (vetoed this release).
- Phase 2.5 `restyle_slides` (retroactive repaint) — effectively subsumed by `generate_variants` + `lock_variant` for new decks; still open for retroactive multi-slide restyle against an already-locked brief.
- New archetype builders.
- Batch `delete_slides` (plural) — D2 intern flagged this as a minor friction; worth considering for v0.5.1 but not in scope here.

## Upgrade notes

- `uv sync` + `uvx slides-mcp install --global` to refresh the skill docs.
- Existing decks + briefs continue to work unchanged — no migration.
- Agent prompts that hand-rolled `updateTextStyle` via `exec_batch_update` continue to work, but should migrate to `update_text_style` for the range-language + auto-thumbnail affordances.
