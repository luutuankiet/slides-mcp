# v0.7.0 — Approve before you commit

*Shipped 2026-04-23. PIL-backed preview primitives + theme discipline tools.*

v0.7.0 closes the "fast-switch variant approval" gap raised at the v0.6.0
session close. The deck agent can now let a human eyeball theme / tone /
accent / font / shape variants **before any slide is written**, and run a
closed-loop "did the deck stick to its brief?" check before shipping.

## Highlights

| Axis | What shipped | Why it matters |
|------|--------------|----------------|
| **Preview before commit** | `render_brief_swatch` + `render_brief_swatch_grid` | One PNG → human eyeballs N candidate tones in 2 seconds. Zero Slides API calls. Zero deck writes. |
| **Font axis in the brief** | `brief.font_family.{heading, body}` + `list_font_pairings` + builder overlay + `propose_brief_variants` carries fonts | Brief now carries a full-stack identity. Six curated Google Fonts pairings ship out of the box, mood-tagged. |
| **Archetype dry-run** | `preview_archetype(archetype, content, brief)` | Compare layouts for the same content before committing via `create_slide`. Pure PIL sketch, 1200×675 PNG, "PREVIEW · NOT WRITTEN TO DECK" badge. |
| **Whole-deck eyeball** | `render_deck_contact_sheet(deck_url, slide_ids?, variant_id?)` | Thumbnail grid of every slide in ONE call. `variant_id` filter cuts 18-thumbnail variant comparison to 3 calls. |

## The "Approve before you commit" workflow

```
1. propose_brief_variants(intent, n=3)
          ↓ returns 3 candidate briefs with fonts
2. render_brief_swatch_grid(briefs)
          ↓ ONE PNG shows all 3 tones — human picks
3. set_theme_brief(deck_url, chosen)
          ↓ commit ONCE, all future create_slide inherits
4. create_slide(...) * N
          ↓ every response carries brief_fields_used for observability
5. audit_brief_coherence(deck_url)
          ↓ coherence_score 0..1, slides_with_drift, fix_hint per slide
6. [if score < 0.9] restyle_slides(..., normalize_fonts=True)
7. render_deck_contact_sheet(deck_url)
          ↓ whole-deck visual voice check in ONE PNG
```

Before v0.7.0, steps 2, 5, and 7 didn't exist. Agents either wrote speculative
slides and deleted them, or committed a brief sight-unseen and discovered
palette mismatches at slide-render time.

## Theme discipline tools (Scope H — scope-expanded mid-session)

User raised the "define / extract / ingest / stick to" question at the B → C
boundary: *"is the current tool support token efficiency as in can you
consume the slides meta by batch or consume only the ones you need"* and
*"you need this project to both work high level and low level for ya that's
the best DX."*

Three tools added to close that loop:

**`orient_to_deck(deck_url, outline_limit=30)`** — composite onboarding. Returns
brief + coherence + archetype histogram + dominant font + truncated outline in
one call. The pagination params (`outline_limit`, `outline_offset`) make this
token-efficient on decks of any size — summary fields are constant-size; the
outline is the only thing that scales, and it's capped by default.

**`audit_brief_coherence(deck_url)`** — single closed-loop check. Walks every
non-meta slide, compares observed palette/fonts/shapes to the active brief,
returns `{coherence_score, sub_scores, drift_by_kind, slides_with_drift[:20],
most_common_overrides[:10], next_action_hint}`. Output is constant-size
regardless of deck length.

**`create_slide` lineage** — every response now carries `brief_fields_used:
list[str]`. Lets autonomous loops assert `"palette.accent" in
resp["brief_fields_used"]` to catch silent override drift.

## Token efficiency guarantees

| Tool | Response size |
|------|---------------|
| `orient_to_deck` | ~500 tok with `outline_limit=0`; ~600-900 tok at default 30; scales only via explicit `outline_limit` opt-in |
| `audit_brief_coherence` | Constant-size on any deck (caps on drift lists) |
| `render_deck_contact_sheet` | Default `max_slides=36`; excess truncated with warning tile; narrow via `slide_ids=[...]` or `variant_id=` |
| `render_brief_swatch_grid` | Constant (grid of N tone cards) |
| `preview_archetype` | Constant (single PNG ~1200×675) |

## Backward compatibility

- All existing briefs continue to validate without `font_family` (optional field).
- `restyle_slides(normalize_fonts=False)` is the default — pre-v0.7.0 calls unchanged.
- `create_slide` still returns `brief_applied: bool`; `brief_fields_used` is additive.
- The brief meta-slide schema is v1 unchanged; additions are optional nested keys.

## Fonts — fallback on unavailable TTFs

Swatches render actual TrueType fonts when available (thinkpad ships DejaVu +
Noto + URW Bookman). When a brief specifies a Google Font not installed on the
render host, swatches fall back to a serif-vs-sans heuristic (DejaVu Serif vs
DejaVu Sans). The font family NAME remains annotated on the swatch caption, so
the human knows what the brief asks for even if the render approximates.

For production-grade swatches, install the relevant Google Fonts on the
render host (`fc-list` to inspect). Future: optional bundled TTFs for the 12
curated pairings.
