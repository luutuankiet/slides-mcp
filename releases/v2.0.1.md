# v2.0.1 — `invalid_scope` refresh fix + slide metadata expansion + notes verbosity

A patch with three threads. The OAuth fix was the trigger; the metadata + verbosity work landed in the same release because they came from real-world dogfooding the day v2.0.0 went live.

## 1. The OAuth refresh bug

**Symptom.** Any tool call after the access token expired (~1 hour post-consent) failed with:
```
('invalid_scope: Bad Request', {'error': 'invalid_scope', 'error_description': 'Bad Request'})
```

**Root cause.** v2.0.0 tightened the OAuth scope set in `auth.py` from `[presentations, drive.file]` (v0.x) to `[presentations.readonly]`. `Credentials.from_authorized_user_file(path, SCOPES)` was passed the new narrow SCOPES list, which got attached to the credential object. When the access token expired and `creds.refresh()` fired, the library asked Google to refresh under `presentations.readonly` — but Google's refresh token is bound to the scopes that were *granted at consent*, and `presentations.readonly` is a different scope string than `presentations` (not a subset in the OAuth grant table). Google returned `invalid_scope: Bad Request`.

**The fix.** `auth.py load_credentials()` now calls `Credentials.from_authorized_user_file(path)` without passing SCOPES. The library uses whatever scopes are saved in the token JSON — refresh asks for those exact scopes, which Google grants. The v2 SCOPES list is still used for fresh `slides-mcp-auth` consent (where it correctly requests only `presentations.readonly`).

Net effect:
- v0.x tokens (`presentations` + `drive.file`) keep working untouched. Capability ≠ usage; v2 tools never make write calls.
- New consents under v2 mint readonly-only tokens.
- Token-refresh path is robust regardless of which version minted the token on disk.

## 2. Slide metadata expansion

Dogfooding v2.0.0 on a real 68-slide draft surfaced a gap: agents had no way to tell which slides were hidden, what their deck position was, or which layout backed them. For an agent scanning a draft to summarize structure, those are first-class metadata.

Three fields added across all detail modes:

| Field | Source | Emit rule |
|-------|--------|-----------|
| `position` | 1-indexed deck order | always (when known) |
| `hidden` | `slideProperties.isSkipped` | only when `true` (omit when visible) |
| `layout_id` | `slideProperties.layoutObjectId` | only when set |

`DECK_OUTLINE_FIELDS` and `SLIDE_FULL_FIELDS` extended with `slideProperties.isSkipped` and `slideProperties.layoutObjectId`. New `normalize.is_hidden()` and `normalize.layout_id()` helpers. `_resolve_slide_ids` selector now accepts `{"hidden": true|false}` to filter by visibility.

Live-verified on a 68-slide deck with 43 skipped slides: outline returned all 68 with `position`+`layout_id`+`notes_chars`; `{"hidden":true}` selector returned exactly 43.

## 3. Notes verbosity (raised body + uncapped notes)

The second dogfooding gap: working decks often park the narrative in speaker notes rather than slide bodies. v2.0.0's `summary` mode capped notes at a 200-char preview, which made agents blind to drafts where 80% of the content lived in notes.

User directive: *"if agents can't read the draft down to the text and image level this whole tool is a bust… include notes metadata. i don't care if including these meta increase token body it's a tradeoff to get you agents in control what the decks are about. maximum verbosity please."*

Changes:

| Mode | v2.0.0 | v2.0.1 |
|------|--------|--------|
| `outline` | no notes body | `notes_chars` (count only, still cheap) |
| `summary` | body cap 600, per-line cap 140, `notes_preview` (200 char) | body cap **1500**, per-line cap **200**, **full `notes` verbatim** + `notes_chars` |
| `full` | body cap; `notes_preview` | **no body cap**; **full `notes` verbatim** |
| `raw` | full notes | full notes (unchanged) |

Per-slide token budget table updated: outline 20→30, summary 80→150, full 150→300, raw 400→600.

The `notes_preview` field is gone. Always `notes` (full) + `notes_chars`. Live-verified: a slide with 2185-char notes returned all 2185 chars in `summary` mode.

## 4. Selector + docs polish

- `slides={"hidden": true|false}` selector documented + tested
- README detail-mode tables updated for new fields and budgets
- README auth-setup hardened: `slides-mcp-auth` invocation now shows the absolute `--out ~/.config/slides-mcp/token.json` to dodge the CWD trap
- README new `## Troubleshooting` section: `invalid_scope` symptom + remediation + canonical-path note

## Migration

No action needed. Existing v2.0.0 installs hit the OAuth bug on first refresh after install (~1 hour after consent). Upgrade to 2.0.1 and the next refresh succeeds.

If you ran `slides-mcp-auth` between v2.0.0 install and the bug surfacing: nothing to undo. The new readonly token works on 2.0.1 (and would have worked on 2.0.0 if the load path hadn't forced narrow SCOPES).

If you wrote token to `./token.json`: move it. See README → Troubleshooting → "Server says no token at...".
