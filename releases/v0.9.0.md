# v0.9.0 — Meta slide durability + brownfield scaffold

## TL;DR

Two changes with one shared thesis: the meta slide is the ONLY persistence
channel for per-deck DNA, so it must be **durable** AND **re-creatable** from
the deck itself.

1. **Durability** — the meta slide now self-documents at first glance:
   - Body `WARNING_PREAMBLE` expanded with explicit `scaffold_meta_brief`
     rebuild command
   - Speaker notes populated on creation via a new `SPEAKER_NOTES_TEXT`
     constant (longer-form explanation + full MCP tool list)
   - Existing `isSkipped=True` + `DO NOT DELETE` marker preserved
2. **Brownfield scaffold** — new `scaffold_meta_brief` tool collapses the
   3-call `get_theme_brief → extract_theme_brief → set_theme_brief` dance
   into one call. `auto_commit_if_high_confidence=True` auto-commits when the
   palette extraction is confident. Brownfield is the dominant entry mode;
   it now takes one tool call instead of three.

## Why it matters — vision reconciliation

The stateless-server + DNA-in-deck invariant (Decision R/S) only holds if
the meta slide survives. A cryptic-looking slide gets deleted by the next
human who opens the deck. v0.9.0 closes that loop:

- The slide **self-documents** → humans don't delete it.
- If deleted anyway → `scaffold_meta_brief` **self-heals** from the deck's
  existing palette.

Brownfield primacy: most decks already exist with content, colors, fonts.
Forcing a 3-tool dance every time breaks the autonomous-loop contract.
One-shot scaffold makes brownfield the default, not the edge case.

## New tool

### `scaffold_meta_brief(deck_url, auto_commit_if_high_confidence=False)`

Brownfield one-shot entry. Replaces the legacy 3-call dance.

| Input state | Returns |
|---|---|
| Meta exists and parses | `status: "exists"` + current brief |
| Meta absent/corrupted, `auto_commit=False` | `status: "proposed"` + proposed_brief + evidence + confidence |
| Meta absent/corrupted, `auto_commit=True` AND `confidence=="high"` | `status: "created"` + committed brief + slide_id |

Proposal comes from the existing `extract_brief_from_prez` heuristic:
palette histogram + shape-type topology → proposed brief with confidence
rating. High-confidence decks auto-commit; low-confidence proposals come
back for user review.

On commit, the meta slide's marker + body + **speaker notes** are all
populated with rebuild instructions — the next human who finds the hidden
slide has full context in situ, no external docs needed.

## Durability additions

### Expanded `WARNING_PREAMBLE`

Body text on the meta slide now includes explicit rebuild commands:

```
Rebuild if deleted: scaffold_meta_brief(deck_url) proposes a brief from the
deck's existing palette; review and commit via set_theme_brief. One-shot for
high-confidence decks: scaffold_meta_brief(deck_url, auto_commit_if_high_confidence=True).
```

Applies retroactively — every `set_theme_brief` / `update_theme_brief` call
emits the new preamble since it lives inside `serialize_brief()`.

### New `SPEAKER_NOTES_TEXT`

Populated into the meta slide's speaker notes on creation by
`set_theme_brief`. Content: what the slide is, why it exists, how to
rebuild (Google Slides version history OR `scaffold_meta_brief`), and the
full MCP tool list. Humans opening the Notes pane get complete context
without external docs.

Implementation: `server.py::_populate_meta_slide_notes` does a second
`batchUpdate` after the main create flow. Discovery of the notes
placeholder goes through `_find_notes_placeholder_id` which walks
`slides[].slideProperties.notesPage.pageElements[]` for the BODY
placeholder. Best-effort — any failure surfaces as a warning, doesn't fail
meta creation.

## Deferred to next session

- **`plan_deck`** — no tool today proposes deck-level narrative
  restructuring. The "high-level reconcile if the deck matches the central
  narrative" leg of the vision is unmet. Advisor-ranked #1 critical. Meta
  slide can carry the committed plan as a second hidden field alongside
  the brief.
- **Archetype registration** — bundled archetypes load from disk at
  startup; the agent can't materialize novel layouts without a server
  restart. Proposed pattern C (hybrid: bundled + deck-embedded overlay via
  meta slide) preserves the stateless invariant while letting the agent
  extend per-deck.
- **`apply_brief_and_restyle` create path** — doesn't populate speaker
  notes on its rebuild branch yet. Minor follow-up; `scaffold_meta_brief`
  handles the primary brownfield entry path.

## Breaking changes

None. `WARNING_PREAMBLE` and `SPEAKER_NOTES_TEXT` expansions are additive
content in the meta slide body / notes. Existing decks continue to parse
(`parse_brief_body` tolerates any preamble size by splitting on `\n---\n`).
`scaffold_meta_brief` is a new tool, not a replacement.
