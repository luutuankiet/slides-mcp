# v0.2.0 — Skill package: `uvx slides-mcp install`

This release adds a **Claude Code skill** describing how to use slides-mcp's 17 tools effectively, and the **`uvx slides-mcp install`** command to drop it into any project (or your user-level skills directory).

## The story

slides-mcp v0.1.1 shipped 17 tools across a 4-layer architecture (auth → DSL → theme → MCP surface). What it didn't ship: *how to USE those tools effectively.* Tool descriptions alone don't cover:

- Which tool to reach for first (bespoke beats escape-hatch; `patch_slide` beats hand-rolled `batchUpdate`)
- When to flip the opt-in `include_elements` geometry channel
- How to navigate clean / faithful / `_object_ids` read modes
- The audit → promote-OR-fix theme-hygiene loop
- `exec_batch_update` dry-run discipline

v0.2.0 packages all of that as a Claude Code skill: one `SKILL.md` + six `rules/*.md` files, installed via:

```bash
uvx slides-mcp install              # $CWD/.claude/skills/slides-mcp/
uvx slides-mcp install --global     # ~/.claude/skills/slides-mcp/
uvx slides-mcp install --path /custom/dir
```

## New CLI surface

`slides-mcp` is now a subcommand dispatcher:

| Invocation | Effect |
|------------|--------|
| `slides-mcp` (no args) | Start the MCP stdio server (unchanged behavior for MCP clients) |
| `slides-mcp install` | Install the skill docs (NEW) |
| `slides-mcp auth ...` | Run OAuth consent (moved under the dispatcher; back-compat `slides-mcp-auth` entry preserved) |

The previous `slides-mcp = "slides_mcp.server:main"` script is now `slides-mcp = "slides_mcp.cli:main"`. MCP clients that invoke `slides-mcp` with no args get the identical stdio server as before.

## What's in the skill

`skills/slides-mcp/SKILL.md` — tool priority table ("bespoke first, escape hatch last"), tools overview (17 entries, 1-liner each), and links out to:

- `rules/workflow.md` — decision tree: "I want to X, use Y"
- `rules/read-deck.md` — outline, slide, search, faithful vs clean, `include_elements` gating
- `rules/write-deck.md` — `patch_slide` semantics, `_object_ids`, translation writes, `clone_deck` replacements
- `rules/theme-hygiene.md` — audit → decide per-drift → promote OR fix
- `rules/bidi-edit.md` — the see-and-move loop; why RELATIVE transform matters; EMU math
- `rules/escape-hatch.md` — `exec_batch_update` safety; destructive denylist; audit log

## Packaging notes

The `skills/` directory lives at the repo root (peer of `src/`). Hatchling `force-include` mounts it at `slides_mcp/_skills_data/` inside the built wheel so the install command can find it whether you ran `uv sync` (editable) or `uv pip install slides-mcp` (wheel).

Source-of-truth lives at `skills/slides-mcp/` in the repo. `.claude/skills/` is the install *target*, not stored in this repo.

## What's NOT in this release (deliberate)

- **No PyPI publish wiring.** The `publish:` job in `.github/workflows/release.yml` remains commented out pending OIDC Trusted Publisher setup on pypi.org. Wheel + sdist are still attached to the GitHub Release; `uv tool install` from the GitHub artifact URL works today.
- **No MCP server auto-registration.** `slides-mcp install` copies skill docs only; it never touches your MCP client config. If you want the slides-mcp server wired into Claude Code, run `claude mcp add slides-mcp uvx slides-mcp` yourself.
- **No re-install / uninstall subcommands.** Install is idempotent (overwrites). For uninstall: `rm -rf .claude/skills/slides-mcp/`.

## Design notes

The shape follows `looker-mcp-shim` (Node, the sibling project): one namespace, `SKILL.md` + `rules/*.md` split, three target modes (`--global` / `--path` / default-cwd), hardcoded `.claude/skills/` destination. The install layer is Claude-Code-specific today because only Claude Code auto-loads skills from a well-known directory; the *content* of the skill is framework-agnostic (no Claude-specific jargon) so it can be broadened to other MCP clients later without rewriting the rules.
