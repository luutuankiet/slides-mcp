# v0.11.0 — plan_deck + theme_swap tools + plan-field primer

## TL;DR

The schema extensions that landed in v0.10.0 (`brand_assets` + `plan`) finally
get the two tools they were shaped to power:

1. **`plan_deck`** — propose + commit a deck-level narrative plan (vision /
   sections / slides / worklog) from free-text intent, a brownfield deck, or a
   markdown doc. The deck-level gsd-lite footprint stored alongside the
   visual brief on the hidden meta-slide.
2. **`theme_swap`** — one-call client-ready clone: clone source deck, apply a
   target brief, swap brand assets (text + image), update the new deck's brief
   `brand_assets.match`. Text-mode + image-mode both ship in this release.
3. **Speaker-notes primer refresh** — the meta-slide's human-readable preamble
   and speaker notes now explain the plan field and point readers at
   `plan_deck` for edits. No more deleting the hidden slide because "what's a
   `plan:` block?"

## Why it matters

v0.10.0 shipped the brief schema but the tools that consumed it were deferred
(see `releases/v0.10.0.md` § "Deferred to next release"). That left a gap:
agents could READ a `plan` or `brand_assets` dict but had no way to write one
without hand-rolling `write_theme_brief(mode="merge", delta={...})`. v0.11.0
closes that gap in one release — schema + tools in sync.

For the brownfield theme-swap case (e.g. the Joon Solutions deck at
`1IIPT_6F-s35EK9ZLPk0xTzDkt4evmNoFDyCIfPOkQLQ`): the four-step ceremony
(clone → read brief → restyle → replace text) collapses to `theme_swap(source,
new_title, target_brief_delta, asset_overrides, confirm_destructive=True)`.

## New tools

### `plan_deck`

```python
plan_deck(
    deck_url: str,
    intent: str = "",
    source: str = "free_text",  # "free_text" | "brownfield_deck" | "doc"
    doc_path: str | None = None,
    commit: bool = False,
) -> dict
```

Source modes:

- **`free_text`** (default): `intent` → `plan.vision`. Empty sections/slides.
  Confidence: `low`.
- **`brownfield_deck`**: walks the existing deck outline; archetype transitions
  (cover_with_hero / section_opener) split it into sections; per-slide intents
  from titles. Confidence: `medium`.
- **`doc`**: markdown at `doc_path`; H1 joins into vision, H2 becomes
  sections + slide intents. Confidence: `medium` when ≥2 H2s found.

Pure proposal by default. `commit=True` merges `{plan: ...}` onto the brief
via `write_theme_brief(mode="merge")`. No meta-slide → returns
`status="proposed"` + warning pointing to `write_theme_brief(mode="scaffold")`.

Return shape:

```python
{
    "deck_id": ...,
    "status": "proposed" | "committed",
    "plan": {"vision": ..., "arc": ..., "sections": [...], "slides": [...], "worklog": [...]},
    "proposal_source": "free_text" | "brownfield_deck" | "doc",
    "confidence": "high" | "medium" | "low",
    "next_step_hint": ...,
    "warnings": [...],
}
```

### `theme_swap`

```python
theme_swap(
    source_deck_url: str,
    new_title: str,
    target_brief: dict | None = None,        # wholesale replace
    target_brief_delta: dict | None = None,  # deep-merge
    asset_overrides: dict[str, str] | None = None,  # {asset_id: new_value}
    confirm_destructive: bool = False,  # REQUIRED True
) -> dict
```

Flow:

1. Read source brief — must have `brand_assets` to swap.
2. `clone_deck(source_deck_url, new_title)` → new deck.
3. Apply `target_brief` (wholesale) or `target_brief_delta` (merge) via
   `apply_brief_and_restyle` on the new deck. Skipped when both are None.
4. For each `(asset_id, new_value)`:
   - **`type: "text"`** → one `replaceAllText` request per swap, scoped to
     the new deck
   - **`type: "image"`** → one `replaceImage` request with `imageObjectId =
     asset.match`, `url = new_value`, `imageReplaceMethod = CENTER_INSIDE`
5. Update `brand_assets[i].match` in the new deck's brief for text swaps
   (image shape objectIds stay stable so no refresh needed).

Exactly one of `target_brief` / `target_brief_delta` must be non-None, or both
None (asset-swap only). `confirm_destructive=True` required.

Return shape:

```python
{
    "source_deck_id": ...,
    "new_deck_id": ...,
    "new_deck_url": ...,
    "assets_swapped": [{"id": ..., "type": ..., "old_match": ..., "new_value": ...}, ...],
    "restyle_applied": bool,
    "warnings": [...],
}
```

### Speaker-notes primer refresh

- `WARNING_PREAMBLE` — adds a line flagging the plan field + pointing to
  `plan_deck`.
- `SPEAKER_NOTES_TEXT` — new `About the plan field` section explaining the
  plan's role (vision/sections/slides/worklog as gsd-lite analogs).
  `plan_deck` added to the tools list.

Edits apply retroactively on the next meta-slide recreate (set_theme_brief
create path) and for any new meta-slides produced by `scaffold_meta_brief`.

## Use cases unblocked

Schemas added in v0.10.0 are now consumable end-to-end:

**brand_assets:**

```python
# v0.10.0: schema existed but no tool wrote it
write_theme_brief(deck_url, mode="merge", delta={"brand_assets": [...]})
# v0.11.0: tool-driven
theme_swap(source_url, new_title="Acme Corp pitch",
           target_brief_delta={"palette": {...}},
           asset_overrides={"client_name": "Acme Corp", "date": "April 2026"},
           confirm_destructive=True)
```

**plan:**

```python
# v0.10.0: schema existed but no tool wrote it
write_theme_brief(deck_url, mode="merge", delta={"plan": {...}})
# v0.11.0: tool-driven
plan_deck(deck_url, source="brownfield_deck", commit=True)
```

## Deferred

- **`scaffold_meta_brief` plan extension** — currently scaffolds the brief
  only. A future patch can extend it to optionally scaffold an empty plan
  alongside. Low-priority: `plan_deck` already handles the plan-lifecycle
  use case.
- **`archetype_hint` validator tightening** — `plan.slides[].archetype_hint`
  still accepts any string; could validate against the archetype registry.
  Kept tolerant per v0.10.0 design (shape tightens when `plan_deck` surface
  matures).
