# v0.10.0 — Moderate tool-surface trim + brand_assets / plan schema

## TL;DR

Two changes, one thesis: **the MCP tool surface is API for agents — discipline it.**

1. **Tool surface trim (49 → 32 tools, 35% reduction).** Twenty-two overlapping
   tools collapsed into eight **kind-dispatched dispatchers**. Every existing
   capability preserved through the new surface; no runtime behavior change
   beyond call-site naming.
2. **Brief schema extension** — `brand_assets` (option i) and `plan` fields on
   the theme brief, laying the groundwork for `theme_swap` and `plan_deck` in
   future releases.

## Why it matters

Every `retrieve_tools` call pays the cost of the registered tool surface. At
49 tools, we were loading ~2.7k tokens of registry noise per discovery cycle
before the first tool call. Many of those 49 were thin variants on the same
verb — six `list_*` tools, four ways to write a brief, three audit tools that
differ only in what they audit. Dispatch-by-kind consolidates them into
discoverable groups without losing per-kind semantics.

At the same time, the theme brief is extending to carry **brand identity**
(for theme-swap tooling) and **narrative plan** (for deck-level reconcile
tooling). Getting both in the schema NOW — with empty/optional defaults —
means the next two features (`theme_swap`, `plan_deck`) land against a
settled shape instead of another round of schema churn.

## Tool surface trim (BREAKING)

22 MCP tool names retired. 8 new dispatchers introduced. Migration map:

| Retired (count) | Replacement dispatcher |
|---|---|
| `list_themes, list_archetypes, list_icons, list_font_pairings, list_catalog_briefs, list_deck_layouts` (6) | `list_registry(kind, filter=?, deck_url=?)` |
| `set_theme_brief, update_theme_brief, scaffold_meta_brief, import_brief` (4) | `write_theme_brief(mode, brief?, delta?, yaml_source?, is_path?, auto_commit_if_high_confidence?)` |
| `audit_deck_colors, audit_typography, audit_brief_coherence` (3) | `audit(kind, slide_ids?)` |
| `update_text_style, update_paragraph_style` (2) | `update_text(scope, ...)` |
| `render_brief_swatch, render_brief_swatch_grid, render_deck_contact_sheet, preview_archetype` (4) | `preview(kind, ...)` |
| `render_thumbnail_url` (+ `render_thumbnail` behavior preserved) | `render_thumbnail(..., mode="bytes"\|"url")` — `mode="bytes"` default, preserves existing callers |
| `tweak_brief + preview_brief_tweak` (2) | `tweak_brief(..., preview="none"\|"slides")` |
| `save_brief_to_catalog, use_catalog_brief` (2) | `catalog_brief(op, ...)` |

**Unchanged:** `apply_brief_and_restyle` (destructive one-call ceremony stays distinct), `list_slides_by` (multi-filter schema doesn't fit dispatcher), core slide primitives (create / delete / patch / duplicate / clone / shape / image / icon), `render_thumbnail` default semantics (bytes mode preserves prior callers), variant workflow (propose / generate / lock — linear state machine stays explicit).

**Validation on dispatchers:** each dispatcher raises `ValueError` with enum-listing messages on missing required kind-specific params or unknown kind.

**Runtime semantics:** no behavior changes beyond naming + dispatch. Underlying library functions unchanged — dispatchers delegate with validated params. Callers that `from slides_mcp.server import old_tool_name` still resolve (only the `@mcp.tool()` decorator was stripped; the functions remain importable).

## Schema extension

`theme_brief` gains two optional top-level fields. Both default-empty; no migration needed for existing briefs.

### `brand_assets` (text-first v1)

Designed for the future theme-swap workflow — clone a deck, swap client-specific text/images, keep content. Schema:

```yaml
brand_assets:
  - id: client_name          # stable, unique slug
    type: text               # text | image
    match: "Joon Solutions"  # exact text for type=text; shape objectId for type=image
    role: client             # client | vendor | co_brand | tagline | date | other
    replaceable: true        # default true; false = product/vendor names that stay
```

Validates: `id` non-empty + unique within list, `type` in enum, `match` non-empty, optional `role` in enum, optional `replaceable` is bool. Merges wholesale on update (list replace in `merge_brief` — existing semantics).

### `plan` (seed for `plan_deck` tool)

Opt-in deck-level narrative skeleton. Shape mirrors gsd-lite's own structure:

| gsd-lite analog | plan field |
|---|---|
| PROJECT.md | `vision` + `arc` (free-text) |
| ARCHITECTURE.md | `sections` + `slides` (ordered intents with optional `archetype_hint`) |
| WORK.md | `worklog` (list of decisions + pivots during build) |

Tolerant validator — shape will tighten when the `plan_deck` MCP tool lands.
