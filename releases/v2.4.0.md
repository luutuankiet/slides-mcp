# v2.4.0 — Run slides-mcp as a shared remote server

slides-mcp can now run as one remote MCP server for a whole team, on Google
Cloud Run, with every person acting as their own Google account. Running it
locally over stdio with `token.json` is unchanged and is still the default.

## New: `slides-mcp serve-http`

- **Stateless streamable HTTP.** No sessions and no standing event stream, so
  an idle connection costs nothing on a scale-to-zero service. Clients on the
  older `initialize` handshake are served on the same endpoint. `GET /mcp`
  returns `405`.
- **Standard MCP sign-in that the client starts on its own.** slides-mcp is
  its own OAuth authorization server and relays sign-in to Google. Clients
  register by dynamic client registration or a client ID metadata document,
  then hold only a token slides-mcp issued. Each person's Google tokens stay
  on the server.
- **Each caller is themselves.** Every Slides call uses the caller's own
  Google access token; `token.json` is never read in this mode.
  `auth_status` reports the caller's email and scopes.
- **Settings are checked before the port opens.** Four environment variables
  are required; anything missing or invalid is listed in one message and the
  process exits with code `2`. `slides-mcp serve-http --help` lists them.
- **Sign-ins live in a dedicated, named Firestore database**, so they survive
  redeploys and scale to zero. Install the `http` extra
  (`slides-mcp[http]`) for it; the repo's `Dockerfile` does.

Setup, from the Google Cloud project to the deploy command:
`docs/deploying-to-cloud-run.md`.

## Changed

- **Unknown tool arguments are now rejected.** The server moved from the
  `mcp` 1.x SDK to `fastmcp` 4, whose tool schemas set
  `additionalProperties: false`. A misspelled argument is now a validation
  error instead of being silently ignored.
- **Agents are told to load the skill.** Every tool description except
  `install_skill`'s now ends with one `Skill:` sentence: load the slides-mcp
  skill once per session, through the agent's own skill loader if the skill
  is installed, otherwise by calling `install_skill`. The server's MCP
  `instructions` say the same. Web agents, which have no skill folder,
  rarely called `install_skill` before. An agent loading the skill this way
  reads it as reference and installs nothing.
- Tool input schemas now carry a description for each parameter.
  `auth_status`'s description now also covers HTTP mode.
- `slides-mcp <word>` with an unknown bare word now exits with
  `unknown command: <word>` (code `2`) instead of starting the stdio server.
  Arguments starting with `-` still start it, so MCP clients' own flags keep
  working.
- The server reports slides-mcp's own version to MCP clients on connect,
  not the SDK's.

## Upgrade notes

- No tool was added, removed or renamed. `uvx slides-mcp@latest` picks this
  up with no configuration change.
- Agents that passed extra, unused arguments to a tool will now get an error
  naming the argument. Drop it and retry.
