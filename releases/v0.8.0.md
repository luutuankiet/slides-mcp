# v0.8.0 — Live brief iteration + portable catalog

*Shipped 2026-04-23. Natural-language brief tweaks, human-visible slide previews, one-call commit+repaint, cross-deck brief library.*

v0.8.0 closes the "alter a live brief conversationally" loop. The agent now
takes a directive like "warmer and more editorial," computes a delta, writes
real sample slides into the deck under the candidate brief for the **human**
to eyeball (not a PIL swatch only the agent sees), and can commit+repaint in
one call. Briefs approved on one deck move to another via a user-owned
catalog or a portable YAML string.

## Highlights

| Axis | What shipped | Why it matters |
|------|--------------|----------------|
| **Directive → delta** | `tweak_brief(deck_url, directive)` + pure `compute_directive_delta` | Six heuristic axes (warmer/cooler, saturation, surface value, shape_language, font pairing by mood, numbering). Unresolved terms bubble up so the agent can surface a human-in-loop clarification. |
| **Human-visible preview** | `preview_brief_tweak(deck_url, candidate_brief, …)` | Writes 2–4 actual slides into the deck under the candidate brief (and the current brief when one exists) so the user opens Google Slides, flips through, picks. Meta-slide restored to original at end — preview is non-persistent. |
| **One-call commit+repaint** | `apply_brief_and_restyle(deck_url, brief=\|delta=, slide_ids=, normalize_fonts=, confirm_destructive=True)` | Collapses the old `update_theme_brief` + `restyle_slides` ceremony into a single call with a unified response. |
| **Portable brief catalog** | `list_catalog_briefs`, `save_brief_to_catalog`, `use_catalog_brief` | `$XDG_CONFIG_HOME/slides-mcp/briefs/<id>.yaml` — 100% user-owned, never bundled with the server. Promote an approved brief from deck A, use it on deck B. |
| **Export/import bridge** | `export_brief(deck_url)`, `import_brief(deck_url, yaml_source, is_path=)` | Deck ↔ YAML string round-trip. Accepts bare brief OR catalog envelope shape. Useful for out-of-band sharing (review docs, VCS repos). |

## Scope rework mid-session

The first cut of v0.8.0 shipped a PIL-based `render_brief_diff` tool (side-by-side
swatch as MCP ImageContent). User pushback: **"that's agent-only — we humans
see through the actual slides or draft slides created."** Dropped
`render_brief_diff` before release, reworked Scope B into `preview_brief_tweak`
which composes on top of `generate_variants` to write real slides the human
can open in Google Slides.

Pattern going forward: **PIL primitives are agent-side sanity checks**;
actual-slide writes are the human approval gate.

## Anchor preserved (Decision R/S)

The theme brief lives in the deck's hidden meta-slide. All v0.8.0 tools
respect this:

- `tweak_brief` reads current brief from meta, fails with a brownfield hint
  if no meta exists ("call `extract_theme_brief` → `set_theme_brief` first").
- `preview_brief_tweak` temporarily swaps meta via `generate_variants`, then
  restores the original brief at the end.
- `apply_brief_and_restyle` commits to the meta-slide and then restyles.
- `use_catalog_brief` / `import_brief` always go through `set_theme_brief`
  — catalog never touches the deck directly.
- The catalog is a **library**, orthogonal to the meta-slide. A user can
  delete the catalog dir without losing any deck state.

## Canonical loop

```
1. get_theme_brief(deck_url)               # brownfield? extract_theme_brief first
2. tweak_brief(deck_url, "warmer and more editorial")
      → {delta, candidate_brief, matched_axes, confidence, ...}
3. preview_brief_tweak(deck_url, candidate_brief=candidate_brief)
      → writes 4 real slides (2 current + 2 candidate) into the deck
      → HUMAN opens Google Slides, picks
4. apply_brief_and_restyle(deck_url, brief=candidate_brief,
                           confirm_destructive=True)
      → commits candidate to meta + repaints every existing slide
5. (optional) save_brief_to_catalog(deck_url, name="Client X warm",
                                    mood_keywords=["warm","editorial"])
      → reuse on the next deck via use_catalog_brief
```

## Known gaps (next up)

Advisor-reconciled gap list (see `gsd-lite/WORK.md` LOG-027 for the full report):

- **Critical:** `plan_deck(deck_url|intent)` — no tool today proposes
  deck-level narrative restructuring / central-points editing. The
  "high-level" half of the vision is missing.
- **Important:** `rules/theme-coherence.md` anti-pattern #4 is stale
  (still says `restyle_slides` isn't shipped — it shipped in v0.6.0).
  `rules/variant-generation.md` Step 3 still shows the pre-v0.7.0
  thumbnail loop instead of `render_deck_contact_sheet`.
- **Important:** extend `compute_directive_delta` synonym table — "dark
  mode", "professional", "high contrast", "less busy" currently fall
  through to `unresolved_terms`.
- **Important:** `table_slide` + `logo_strip` content builders — two of
  the four remaining archetypes without builders, both common in
  consulting decks.
- **Transparency:** `preview-workflow.md` doesn't distinguish agent-only
  (PIL) vs human-visible-via-deck previews. Add a Visibility column.
